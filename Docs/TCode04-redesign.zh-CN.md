# V4 前瞻与设备限值协商：重设计方案

状态：2026-10-12 已实现首版限值协商、固定比例缩幅、量化复核、受限定位和设备入队校验。
主机/固件原生队列测试及两个项目编译通过；未完成板上运行时间和机械实测。

首版实现范围：协商现有六个归一化运动限值，配置版本跟踪这六个参数；
机械映射/逆运动学约束尚未纳入此协商。过限报错目前使用类型码 9，尚无轴/节点详细诊断。
位置编码、时间间隔和曲线形式由固定模型 1 定义，不作为额外可变能力字段返回。
消息格式以协议仓库 `spec/0.4-buffered.md` 的实现后更新为准。

## 已确认目标

- 设备是运动限值的权威来源，上位机读取设备当前生效的限值后规划。
- 超限时优先保持视频同步、缩小动作幅度，不在播放中延长时间追赶。
- 反向节点要求参考轨迹的速度、加速度、jerk 均为零。
- 重计算放在电脑；P4 负责独立校验、缓冲、按时采样和执行。
- 原有设备配置不能被轨迹自身的峰值、上位机报送的包络或隐藏的限值放大覆盖。

## 数据流

1. MFP 查询设备能力、启动标识、配置版本和当前生效运动限值。
2. 设备返回轴映射、位置编码/单位、位置范围、V/A/J 上限、插值模型版本及队列约束。
3. MFP 处理 Funscript 的时间偏移、播放速度、行程设置和节点提取，生成满足设备限值的轨迹。
4. BEGIN 绑定启动标识、配置版本和插值模型版本。
5. APPEND 发送调整后的时间/位置节点。P4 独立计算每段峰值，整帧校验通过才入队。
6. ARM、执行、SEAL、STOP 沿用会话和绝对设备时间语义。

能力/限值响应使用独立报文，不能无条件改变已有的 22 字段状态 ACK。
已与固件协议仓库统一：查询操作 6，响应类型 101（20 字段），BEGIN 增加限值版本与模型号。
不支持限值协商的旧固件必须明确报不支持，不能静默回退到旧的无限值缓冲路径。

## 限值契约

- 返回实际当前值，不仅返回预设名称或参数可配置的最大值。
- 明确归一化位置、秒及相应导数单位。现固件入队位置为整数乘 0.0001，
  上位机必须按真实编码校验，不能假定整数 9999 精确代表 1。
- 现有平移/旋转参数组可展开为每轴限值。参数分组不代表机械独立：
  L0/L1/L2/R1/R2 为耦合机构，R0 为独立扭转轴。
- 设备位置映射、运动限值或执行模式变化，必须更新配置版本。
- 会话使用一个不可变配置快照。执行中修改配置应先受控制动，再应用新配置、
  重新协商和预装载；不能在已运动状态超出新限值时声称瞬间满足新限值。
- 配置查询应形成一致快照；分包查询过程中发生版本变化则重读。

## 首版规划模型

七次曲线本身不排斥设备限幅。旧实现的错误在于把曲线需要的峰值当成允许上限。
首版可以保留固定的七次插值作为双方约定的解码规则，但所有节点必须先通过限值规划。
上位机求解动作幅度；设备端只做固定次数的算术和相同曲线的采样，不做全局优化。

对于位移 D、时长 T 的七次静止到静止段：

```
Vpeak = 2.1875 * |D| / T
Apeak = 7.5131884044... * |D| / T^2
Jpeak = 52.5 * |D| / T^3
Dallowed = min(Vlimit*T/2.1875,
               Alimit*T*T/7.5131884044...,
               Jlimit*T*T*T/52.5)
```

实际实现需要保守的浮点误差预算，按量化后节点再次检查；不能简单放宽用户上限。
这是轴空间参考轨迹验证，不等于完成逆运动学后的电机空间限值验证。

### 缩幅策略

首版使用一次播放会话内固定的缩幅比例：

```
alpha = min(1, 各活动轴各段的 Dallowed / |D|)
p_adjusted = center + alpha * (p_original - center)
```

首版每轴 center 取用户配置输出范围的中点；零位移段无需参与除法。
固定比例保留节点时间和各轴原始的相对变化关系，避免逐段裁剪终点导致基线漂移。
量化后重新检查全部段；必要时进一步缩幅。不能只检查浮点规划结果。
这会因局部困难动作压缩整段会话，是明确的首版取舍；局部动态缩幅属于后续规划器优化，
必须计入缩放变化自身引入的导数，不能在分段处直接切换比例。

中途开始、暂停后继续、跳转和变速都从调整后的轨迹重新计算初始位置。
定位动作也受限：必要时延长正式播放前的准备时间，不能固定一秒而忽略设备约束。
已提交的轨迹不可就地修改；更换规划须停止旧会话并重新预装载。

## Ruckig 的定位

Ruckig 可以在电脑上用于受限定位、制动以及后续更一般的轨迹规划。
普通 Ruckig 的 jerk 有界不等于端点 jerk 为零，不能宣称简单替换即可同时满足所有要求。
如果改用 Ruckig 输出的分段轨迹，必须同时定义新的插值模型和报文表示；
不能只发其终点，再让设备用七次曲线重建不同的运动。
旧实时 TCode 的设备端 Ruckig 保留；缓冲模式切回实时模式必须连续且遵守会话限值。

## 设备端独立校验

- 校验时间递增、最短/最长间隔、队列空间、位置范围、会话及配置版本。
- 对每个新段计算 V/A/J 峰值，与设备限值比较；超限整帧拒绝且不改变队列。
- 返回限值错误时给出轴、节点时间及超限类型，区分 CRC、过期、队列满等错误。
- 保留 CRC、幂等重试、公共时间基准、迟到拒绝和欠载处理。
- 已知可执行的轨迹包络只能用于数值一致性检查，不能成为设备允许的上限。
- STOP/故障接续禁止通过 max(配置限值, 旧轨迹峰值) 把违规路径重新放行。

## 实现位置与验收

- 固件：能力/限值查询、配置版本、入队检查、执行限值及停止接续。
- MFP：协商、调整后节点生成、量化复核、重新定位、显示缩幅比例。
- 协议文档：单位、模型版本、限值快照和错误响应。
- 验收应覆盖：全幅可行、超限缩幅、量化边界、多轴及 R0、配置变化、旧固件拒绝、
  跳转/变速/停止、传输重试、断流，以及主机规划结果与固件采样的一致性。
- 板上单独测量入队校验耗时、每周期采样耗时和控制周期超时；不能用电脑耗时替代。
