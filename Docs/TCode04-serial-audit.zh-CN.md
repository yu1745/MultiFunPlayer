# V4 限值协商串口审查（2026-10-12）

包头仍为 `!4,`，数字字段、`*`、十进制 CRC32、换行构成完整帧。
新增操作 6 和响应 101 都在此包头内，不增加新的串口前缀。

审查固件 `ctw_esp32s3_0909` 的实际路径：

| 层 | 分发规则 | 与本次报文的关系 |
|---|---|---|
| C3 `src/c3_tx/main.cpp:textByte` | 只截获行首 `@c3 ` | `!4` 按普通控制台字节转发，允许跨多个无线数据块 |
| C3 二进制窗口 | 显式打开 OTA/trace 窗口后转给 `binaryByte`，COBS 使用零字节分隔 | 不是根据 `!` 自动切换；二进制窗口开启时不能同时运行文本 V4 |
| P4 `src/uart/uart.cpp` | 行首 `!` 或 `$` 绕过 Shell 编辑器、回显和补全；255 字节超长整行丢弃 | CRC 不受逐字符回显干扰；继续遵守现有长度上限 |
| P4 `src/executor/executor.cpp` | 先将 `$` 交给配置 API；行首 `!` 进入 `timedTCode`，之后才分发 D 命令、旧 TCode、Shell | 配置与运动前缀隔离；非法/未知版本帧也不会回退到旧动作解析 |
| P4 `include/tcode_queue.hpp` | 版本、数字格式、字段数、CRC32、boot/session 校验 | 新查询只读，不消耗动作序号；BEGIN 额外验证限值版本与模型 |
| MFP 接收器 | 逐行组装，忽略普通日志和提示符；仅接受合法 100/101 响应 | 两种响应分别校验长度，状态 ACK 格式不变 |

协议报文不包含 L/R/I/S/D 等旧动作命令字母。混入这些字母的损坏帧 CRC/格式校验失败，
不会被降级当成旧 TCode。未完成的 Shell 输入、OTA/trace 二进制窗口或并发写入者
不属于可保证互通的边界：连接应使用独占串口，并在文本模式、完整换行边界启动。
P4 在 OTA 锁定期间还会禁止普通控制报文，不能把查询超时误认为需要发送旧协议动作。

验证：生产固件队列原生测试覆盖查询、未知版本、损坏/混合命令、旧 BEGIN 拒绝和原子拒绝。
主机测试覆盖分片 ACK、CRC 错误、相同报文重试及真实队列协议联调。
此次未修改 C3/UART 路由代码；未完成无线链路或实机混流测试。

## 同步新版配置器后的复审

固件远端 `b9d64f0` 包含浏览器配置器。`$<id> verb` 请求返回前后带零字节的 COBS 二进制 CTWA 帧；
请求与 `!4,` 不重叠。MFP 的预设会话停止并等待原动作循环及接收器结束后独占原串口，
通过 `hello` 识别设备、`presets L/R` 查询结构化列表，使用配置 API 的 `set/settemp/sh` 写入。
回复按请求号、版本、CRC32、分包序号/总数校验，不解析终端提示符，不改变 Shell 激活状态。
不重试未确认的写入；超时或损坏的响应无法完成组包时断开输出。关闭后 V4 新会话重新读取限值。
这部分进行了代码审查和 MFP 编译，尚未做实机通信或 UI E2E 验证。
